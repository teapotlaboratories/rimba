The production gate becomes a discoverable 802.11s gate
one setter call · +24 lines · the standalone pre-step S6 Case B depends on

The all-ESP mesh-gate L2 bridge learns proxy paths from proxied data frames, so the production gate app rimba-halow-mesh-ap never needed to announce itself on-air — and never did. S6 Case B (a Linux node discovering the ESP gate the standards way) needs it to emit a Root Announcement with RANN_FLAG_IS_GATE. This is that change, alone: after mmwlan_mesh_start() the gate now calls mmwlan_mesh_set_root_announcements(true, true, 5000) — additive, safe, and verified end-to-end on three boards + a monitor.

✓ All three Part 0 checks PASS — gold-standard live-device A/B

The production gate emits a RANN that is byte-identical to the S1-verified frame (flags=0x01, on-air on chronium); the zero-config round-trip is untouched (STA DHCPs 10.9.9.2 and pings a mesh node 14/14, 0 drops); and a real ESP node peers, receives, and records the gate (known_gates=1) — the standards discovery path S6 Case B rides on.

The change

App-level only, +24 lines, no morselib change. Two files, kept byte-identical below the banner by the T0 clone-mirror guard (0e01d8c):

// firmware/rimba-halow-mesh-ap/main/app_main.c  (and its clone test-mesh-gate-ap)
// RAW numeric on the wire (no ms->TU convert) — MUST equal the Linux bench gate's value.
#define MESH_RANN_INTERVAL_MS 5000
   ...
   mmwlan_mesh_start(&mesh_args);            // (unchanged) mesh vif up
+  mmwlan_mesh_set_root_announcements(/*root_rann=*/true, /*is_gate=*/true, MESH_RANN_INTERVAL_MS);
+  ESP_LOGI(TAG, "==> gate RANN announcements ON (IS_GATE, interval=%dms) on chan %d.", ...);

Why additive/safe: the ESP↔ESP bridge learns proxy paths from proxied data frames, so RANN emission only adds standards gate discovery — it changes no existing datapath. The handoff's load-bearing worry ("is the setter a silent no-op because multihop is off?") is resolved: g_mesh_multihop defaults true (umac_mesh.c:566) and neither app disables it.

⚠ The clone-mirror tripwire

test-mesh-gate-ap is a body-clone of the production gate, guarded by the T0 _check_clone_mirrors check. Editing one app_main.c and forgetting the other FAILs T0 — so the identical two hunks were mirrored into the clone (bodies byte-identical again; make test-unit 46/46). This also correctly makes the harness's Case-C gate emit RANN.

On-air verification

Rig: board0 (e2:72:a1:f8:ef:a4) = gate; board1 = mesh node; board2 = STA; chronium = morse0 monitor (freq 5560 = S1G ch27). Whole bench fw 1.17.8.

(a) Gate emits RANN with IS_GATE — captured on chronium

sa=e2:72:a1:f8:ef:a4  flags=0x01  hop=0  ttl=31  rann_addr=e2:72:a1:f8:ef:a4  interval=5000  metric=0
full_hex=d0000000 ffffffffffff e272a1f8efa4 e272a1f8efa4 9000 0d017e1501001f e272a1f8efa4 0a000000 8813000000000000 <FCS>

Byte-diff vs the S1-verified ESP RANN: every invariant field identical — FC d000, DA ffffffffffff, cat/act 0d01, eid/len 7e15, flags 01, hop 00, ttl 1f, interval 88130000 (5000), metric 0; only SeqCtrl + rann_seq + FCS (per-frame counters) differ. board0's serial confirms the new marker ==> gate RANN announcements ON (IS_GATE, interval=5000ms) on chan 27., with the AP coming up concurrently — no crash.

(b) Zero-config round-trip still works — no retire-L3 regression

associated to "rimba-ping"  ->  DHCP lease 10.9.9.2 — zero-config on the flat mesh subnet
pinging 10.9.9.100 ...       ->  reply from 10.9.9.100 seq=1..14   (23–68 ms, 0 drops, from the FIRST ping)

Identical to the retire-L3 baseline. Adding RANN emission did not perturb the L2-bridge datapath.

(c) A real ESP node learns the gate via RANN

board1 = test-mesh-gate-rx MESH_ID=rimba-mesh (the mesh SAE password rimbamesh2026 is compiled into morselib and identical across rimba-mesh/rimba-smesh, so the Mesh-ID override is enough to peer with the gate app):

joining mesh "rimba-mesh" (SAE) ... estab_peers=1  peer[0]=e2:72:a1:f8:ef:a4  known_gates=1
==> GATE DISCOVERED via RANN (known_gates=1) — S2 RX path works ...

So the production gate's RANN is well-formed enough for a real ESP node to peer, receive, and record it as a gate. (Bonus: board1 concurrently logged AE-rx + MPP learned … via e2:72:a1:f8:ef:a4 — the gate's full proxy machinery runs alongside RANN emission.)

Review

/code-review (xhigh) over the working diff found no correctness findings — the change is additive, minimal, and bench-verified. One low-severity maintainability note: 5000 is now a third independent copy of the bench-wide RANN interval (with the test-mesh-gate-ap mirror and test-mesh-gate's RANN_INTERVAL_MS), with no single source of truth — a future bench-interval change must update every copy and the Linux gate, or the S6 P3 byte-diff breaks. Mitigated by the clone-mirror guard + the in-code comment; consistent with the repo's per-app-constant pattern (MESH_ID, MESH_S1G_CHAN are likewise duplicated). Left as-is.
