Reproducing the AP assert — and finding a second defect behind it

The last part of this epic never reproduced. It reproduces on the first try, and it is two defects rather than one. The session’s real work was proving that its Interrupt WDT is not the relay FIX-1 fault — because assuming it was would have scoped S3 wrongly.

1 · The WDT question, which is what the session was for

The first reproduction showed Interrupt wdt timeout on CPU0 cycling every ~1.5 s. The obvious suspicion was that S3 and FIX-1 (the relay Interrupt-WDT, root-caused as hw_restart’s SPI-host teardown being fatal under bus_lock) were one problem — which would make S3 far larger than “remove an assert”.

They are not the same, and the code settles it with no bench run

  • The AP check is the first statement in hw_restart_evt_handler(). mmdrv_deinit() — the teardown behind FIX-1 — sits further down and never executes on this path.
  • The assert itself fails cleanly: MMOSAL Assert, backtrace, rst:0xc. No watchdog involved.

So the WDT belongs to the boot that follows the reset. Two faults both reporting “Interrupt wdt” is exactly the coincidence that merges unrelated bugs into one wrong theory — and the design doc had already recorded the speculation as a finding.

stagewhatconsequence
1AP vif active → assert → clean resetthe documented defect; fix = recover the AP arm as Linux does
2the reset can leave the node in a boot-time ISR watchdog looponce entered, it cannot reboot its way out

Stage 1’s fix avoids stage 2 by never rebooting, but does not fix it — stage 2 stays reachable by any reset landing mid-restart.

2 · The review caught a trap

Disabling the gate would have failed the fix it exists to certify

The arm neutralised the before ping but left the after one scoring — so once S3 lands and the board survives, data_ok is false by construction and the fixture prints TEST|RESULT|FAIL for a working fix.

The stated reason was also wrong. I had written “no per-vif RX demux, so mesh RX is unwired”. RX was never the problem — mmhalow registers a plain rx cb and umac_datapath falls back to it. What breaks is TX: with a mesh (STA host-slot) and an AP vif both valid, morselib cannot infer the egress vif, logs Unable to infer VIF ID, and drops the packet. One line — mmhalow_set_tx_vif(MMWLAN_VIF_STA), which test-mesh-ap-gate:291 already does — restores a real gate. Bench-confirmed: data-before passes 4/5 with the AP vif up.

Fixing the diagnosis strengthened the finding

With the TX vif correctly pinned, the boot-time WDT still reproduces — 26 consecutive cycles. So it is not an artifact of the mis-configured fixture.

3 · Claims I had to withdraw

  1. “Every boot after that reset dies.” Wrong — it is intermittent. A third run on the same binary and rig recovered cleanly through repeated assert cycles. What is established is that the loop is reachable and self-sustaining once entered, not that it always follows.
  2. “Permanently bricked until power-cycled.” Never tested. Only an ESP software reset is known not to clear it.
  3. “Plausibly the same teardown path as FIX-1.” Disproved — but only the PR description had been corrected, while the design doc still carried the guess.

The pattern in all three

I wrote a section, later learned something that contradicted it, and updated the nearest text rather than every place the claim lived.

4 · Two build traps

  • The partition growth is --gc-sections, not “the arm compiles AP mode in”. CONFIG_HALOW_AP_MODE=y predates the arm; referencing mmwlan_ap_enable() makes the linker retain the AP/hostap subgraph it used to discard. The wrong explanation would send a reader toggling HALOW_AP_MODE to recover flash.
  • TEST_AP_VIF is a CMake cache variable, so the panic arm is sticky: a later plain make build inherits it. Pass AP_VIF=0 or wipe the build dir.

Process note

I mis-read a failed build as successful: my grep filtered out the size-check error and I took a strings hit on the stale binary as confirmation. The honest signal was the absent “Project build complete”. Second time this session that filtering hid a failure.
